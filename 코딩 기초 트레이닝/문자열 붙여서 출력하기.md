# [프로그래머스] 문자열 붙여서 출력하기 (C++)

- 문제 링크: https://school.programmers.co.kr/learn/courses/30/lessons/181946
- 난이도: Lv.0
- 키워드: `std::string`, `cin >>`, 문자열 이어붙이기(concatenation), SSO

---

## 1. 문제 요약

- 공백으로 구분된 두 문자열 `str1`, `str2`를 입력받는다.
- 두 문자열을 **공백 없이 이어서** 출력한다.
- 제한: $1 \le$ `str1`, `str2`의 길이 $\le 10$

| 입력 | 출력 |
|---|---|
| `apple pen` | `applepen` |
| `Hello World!` | `HelloWorld!` |

---

## 2. 풀이 코드

```cpp
#include <iostream>
#include <string>

using namespace std;

int main(void) {
    string str1, str2;
    cin >> str1 >> str2;
    cout << str1 + str2;
    return 0;
}
```

---

## 3. 핵심 개념

### 3.1 `cin >>`는 공백(whitespace)에서 끊어 읽는다

- `operator>>`로 `std::string`을 읽으면:
  1. 앞쪽 공백(space, tab, newline)을 **건너뛰고**
  2. 다음 공백이 나오기 **직전까지** 읽는다.
- 그래서 `apple pen` → `str1 = "apple"`, `str2 = "pen"`
- 공백은 입력 단계에서 이미 빠지므로, 출력은 그냥 붙이기만 하면 된다.

> 공백까지 포함해 한 줄 전체를 읽으려면 `getline(cin, s)`를 사용한다.

### 3.2 `std::string`의 `+` 연산자

- `std::string`은 `operator+`가 **오버로딩(operator overloading)** 되어 있어서 `+`로 이어붙이기가 가능하다.
- `str1 + str2`는 두 문자열을 이은 **새로운 `std::string` 임시 객체(temporary)** 를 반환한다.
- 이 임시 객체는 **전체 표현식(full-expression)이 끝날 때**, 즉 `;`에서 소멸된다.

---

## 4. 메모리 관점에서 보기

### 4.1 `std::string` 객체의 구조

`std::string`은 지역 변수로 선언하면 **객체 자체는 스택(stack)** 에 올라간다.
문자 데이터가 어디에 저장되는지는 길이에 따라 달라진다.

```
[ std::string 객체 (스택, libstdc++ 기준 32 bytes) ]
┌──────────────┬──────────────┬─────────────────────────┐
│ char* ptr    │ size_t size  │ union {                 │
│ (8 bytes)    │ (8 bytes)    │   char local_buf[16];   │ ← 짧은 문자열은 여기에 직접 저장
│              │              │   size_t capacity;      │ ← 긴 문자열이면 capacity 저장
│              │              │ } (16 bytes)            │
└──────────────┴──────────────┴─────────────────────────┘
```

### 4.2 SSO (Small String Optimization)

- 짧은 문자열은 힙(heap)에 할당하지 않고, **객체 내부 버퍼에 직접 저장**하는 최적화.
- 힙 할당(`new`/`malloc`)은 비용이 크기 때문에, 짧은 문자열에서 이를 피하는 것이 목적이다.
- SSO 버퍼 크기는 **표준이 아니라 구현마다 다르다(implementation-defined)**.

| 구현 | SSO로 저장 가능한 최대 길이 (64-bit) |
|---|---|
| libstdc++ (GCC) | 15자 |
| MSVC STL | 15자 |
| libc++ (Clang) | 22자 |

### 4.3 이 문제에 적용해 보면

- `str1`, `str2`는 각각 최대 10자 → **SSO 범위(15자) 안** → 힙 할당 없음
- 그런데 `str1 + str2`는 최대 **20자** → libstdc++에서는 15자를 넘으므로 **힙 할당 발생 가능**

직접 `operator new`를 가로채서 확인한 결과 (g++ 13.3, libstdc++, 64-bit):

```
sizeof(string)=32, empty capacity=15
a.capacity=15 allocs=0          ← 10자 문자열: 힙 할당 0회 (SSO)
a+b:
  [heap alloc 31 bytes]         ← 20자 결과: 힙 할당 1회
c.size=20 allocs=1
```

- 31 bytes = capacity 30 + 널 문자(`'\0'`) 1. 기존 capacity 15를 **2배로 늘린** 값이다.

### 4.4 그래서 더 가벼운 방법은?

```cpp
cout << str1 << str2;
```

- 임시 문자열을 만들지 않고 **각 문자열을 출력 스트림에 바로 넘긴다**.
- 힙 할당도, 복사도 없다.
- 이 문제 규모에서는 체감 차이가 없지만, **매 프레임 수천 번 실행되는 코드**(게임 루프, 렌더링 루프)라면
  불필요한 임시 객체와 힙 할당은 성능 저하와 메모리 단편화(fragmentation)의 원인이 된다.

| 방식 | 임시 객체 | 힙 할당 (libstdc++, 이 문제 최대 입력) |
|---|---|---|
| `cout << str1 + str2;` | 생성됨 | 1회 |
| `cout << str1 << str2;` | 없음 | 0회 |

---

## 5. 복잡도

- 시간 복잡도: $O(n + m)$ ($n$, $m$은 두 문자열 길이)
- 공간 복잡도:
  - `str1 + str2`: $O(n + m)$ 추가 (임시 문자열)
  - `cout << str1 << str2`: $O(1)$ 추가

---

## 6. 정리

- [x] `cin >>`는 whitespace 기준으로 끊어 읽는다
- [x] `std::string`은 `+`로 이어붙일 수 있지만, **새 임시 객체를 만든다**
- [x] 짧은 문자열은 SSO 덕분에 힙 할당이 없다 (버퍼 크기는 구현마다 다름)
- [x] 출력만 할 거라면 `cout << a << b`가 임시 객체·힙 할당 없이 더 가볍다
