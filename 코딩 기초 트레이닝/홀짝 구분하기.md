# 홀짝 구분하기 - 오답노트와 메모리 관점

## 문제
- 자연수 `n`이 짝수면 `"n is even"`, 홀수면 `"n is odd"`를 출력한다.
- 제한: $1 \le n \le 1000$

| 입력 | 출력 |
|---|---|
| `100` | `100 is even` |
| `1` | `1 is odd` |

## 최종 정답

```cpp
#include <iostream>

using namespace std;

int main(void) {
    int n;
    cin >> n;

    if (n % 2 == 0)
    {
        cout << n << " is even" << '\n';
    }
    else
    {
        cout << n << " is odd" << '\n';
    }

    return 0;
}
```

---

## 오답노트: 내가 틀린 부분

간단한 문제인데 정답까지 다섯 번을 고쳤다. 틀린 부분을 하나씩 정리해 본다.

| # | 틀린 코드 | 결과 | 원인 | 수정 |
|---|---|---|---|---|
| 1 | `n / 2 % 0` | 런타임 에러 | 몫과 나머지 혼동, **0으로 나머지 연산** | `n % 2 == 0` |
| 2 | `"is even"` | 오답 | `is` 앞 공백 누락 → `100is even` | `" is even"` |
| 3 | `<< \n;` | 컴파일 에러 | 이스케이프 문자를 따옴표 없이 씀 | `'\n'` 또는 `"\n"` |
| 4 | `else (n % 2 == 1)` | 컴파일 에러 | `else`는 조건을 받지 않음 | `else` 또는 `else if (...)` |
| 5 | `"is add"` | 오답 (1/2 통과) | 철자 오타 (add = 더하다) | `" is odd"` |

### 1. `n / 2 % 0`
- `/`, `*`, `%`는 우선순위가 같고 **왼쪽부터** 계산된다. 그래서 이 식은 `(n / 2) % 0`이 된다.
- `/`는 **몫**, `%`는 **나머지**다. 짝홀 판별에는 나머지가 필요하다.
- `% 0`은 0으로 나누는 연산이라서 **정의되지 않은 동작(undefined behavior)**이다. 아래 메모리 관점 4번에서 자세히 정리했다.

### 3. `\n`을 따옴표 없이 씀
- `\n`은 따옴표 안에 있을 때만 줄바꿈 문자로 해석된다. 따옴표 밖의 `\`는 컴파일러가 해석할 수 없다.

### 4. `else`에 조건을 씀
- 컴파일러는 `else` 뒤의 `(n % 2 == 1)`을 조건이 아니라 **그냥 계산식 하나**로 읽는다. 그 뒤에 `;` 없이 `{`가 나와서 문법 에러가 난다.
- 경우가 두 가지뿐이면 `if`-`else`로 충분하다. 같은 조건을 두 번 검사할 필요가 없다.

### 2, 5. 출력 문자열 실수
> **디버깅 습관:** 테스트가 실패하면 **기댓값과 출력 줄**부터 비교하자. 공백 하나, 글자 하나까지 정확히 맞아야 통과한다.

## 메모리 관점에서 보기

### 1. 짝홀은 마지막 비트 하나로 결정된다
`int`는 보통 32비트(4바이트) 정수이고, 음수는 **2의 보수(two's complement)**로 저장된다. (C++20부터는 표준에서 2의 보수를 보장한다.)

| 값 | 16진수 | 2진수 (하위 8비트) | 최하위 비트(LSB) | 판별 |
|---|---|---|---|---|
| `100` | `0x00000064` | `0110 0100` | **0** | 짝수 |
| `1` | `0x00000001` | `0000 0001` | **1** | 홀수 |
| `-3` | `0xFFFFFFFD` | `1111 1101` | **1** | 홀수 |

- 2진수에서 1의 자리를 뺀 나머지 자리($2^1, 2^2, \dots$)는 전부 2의 배수다. 그래서 **최하위 비트(LSB)가 0이면 짝수, 1이면 홀수**다.
- x86 같은 little-endian CPU에서는 `100`이 메모리에 `64 00 00 00` 순서로 저장된다. 최하위 바이트가 가장 낮은 주소에 온다.

그래서 비트 AND 연산으로도 판별할 수 있다.

```cpp
if ((n & 1) == 0)   // LSB가 0이면 짝수
```

$$n \,\&\, 1 = \text{LSB}(n)$$

> **주의:** `n & 1 == 0`이라고 쓰면 `==`가 `&`보다 먼저 계산되어 `n & (1 == 0)`, 즉 `n & 0`이 된다. **반드시 괄호를 쓰자.**

### 2. 음수와 `%`: `n % 2 == 1`이 위험한 이유
- C++11부터 정수 나눗셈은 **0 쪽으로 버림**(truncation toward zero)한다. 그래서 나머지의 부호는 **왼쪽 피연산자를 따른다.**
- `-3 / 2 == -1`, `-3 % 2 == -1`이다. 결과가 `1`이 아니다.
- 그래서 홀수를 `n % 2 == 1`로 검사하면 음수 홀수를 놓친다.

| 판별식 | `n = 3` | `n = -3` |
|---|---|---|
| `n % 2 == 1` | true | **false** ❌ |
| `n % 2 != 0` | true | true |
| `(n & 1) == 1` | true | true |

- 이 문제는 $n \ge 1$이라서 상관없다. 하지만 오답 4번처럼 `else if (n % 2 == 1)`을 습관으로 들이면 다른 문제에서 버그가 난다. **`else`로 처리하는 게 더 안전하다.**

### 3. `'\n'` vs `"\n"` vs `endl`

| 표현 | 타입 | 메모리 | 동작 |
|---|---|---|---|
| `'\n'` | `char` | 1바이트 값 (`0x0A`) | 줄바꿈 문자 1개 |
| `"\n"` | `const char[2]` | `0x0A`, `0x00` 2바이트, 읽기 전용 영역에 저장 | 줄바꿈 + 문자열 끝 표시 `'\0'` |
| `endl` | 함수 (manipulator) | - | `'\n'` 출력 + **버퍼 flush** |

- 문자열 리터럴은 끝에 **널 문자 `'\0'`**가 붙는다. 그래서 `"\n"`은 글자 하나처럼 보여도 2바이트다.
- `cout`은 출력할 내용을 메모리 **버퍼**에 모았다가 한 번에 내보낸다. `endl`은 매번 버퍼를 강제로 비워서(flush) 출력 장치에 쓰게 만들기 때문에 반복문 안에서 느려진다.

### 4. 0으로 나누기는 왜 프로그램을 죽이나
- C++ 표준에서 `/`나 `%`의 오른쪽 피연산자가 0이면 **정의되지 않은 동작(undefined behavior)**이다.
- 실제로 x86 CPU에서는 정수 나눗셈 명령어(`idiv`)가 0으로 나누면 **하드웨어 예외**를 일으킨다. Linux에서는 이게 `SIGFPE` 시그널이 되어 프로그램이 종료된다. (이름은 "Floating Point Exception"이지만 정수 나눗셈에서도 난다.)
- 이 문제의 `% 0`처럼 0이 상수로 박혀 있으면, 컴파일러가 경고를 띄우거나 코드를 예측할 수 없게 최적화할 수도 있다.

### 5. `%`와 `&` 중 뭐가 빠를까?
- GCC나 Clang에서 최적화 옵션(`-O2`)을 켜면, `n % 2 == 0`도 **LSB 하나를 검사하는 명령어**로 바뀐다. 그래서 짝홀 판별 성능은 같다.
- 두 함수를 `-O2`로 컴파일해서 x86-64 어셈블리를 확인해 보면, 두 컴파일러 모두 **완전히 같은 코드**를 만든다.

```cpp
bool even_mod(int n) { return n % 2 == 0; }
bool even_and(int n) { return (n & 1) == 0; }
```

```asm
; Clang -O2 (두 함수 모두 동일)
test  dil, 1     ; n의 최하위 비트를 1과 AND해서 검사
sete  al         ; 결과가 0이면 true
ret

; GCC -O2 (두 함수 모두 동일)
mov   eax, edi
not   eax        ; 비트 반전
and   eax, 1     ; 최하위 비트만 남김
ret
```

- `div`나 `idiv` 같은 나눗셈 명령어는 하나도 나오지 않는다. 컴파일러가 `% 2`를 비트 연산으로 바꿔준 것이다.
- 컴파일러 버전이나 옵션에 따라 결과는 달라질 수 있다. [Compiler Explorer (godbolt.org)](https://godbolt.org)에서 직접 확인해 보자.
- `&`는 셰이더(HLSL/GLSL)의 비트 패킹, 플래그 검사 같은 저수준 코드에서 자주 쓰인다. 개념은 꼭 알아두자.

## 정리
- `/`는 몫, `%`는 나머지. `/`, `*`, `%`는 우선순위가 같고 왼쪽부터 계산
- 0으로 나누기(`/ 0`, `% 0`)는 undefined behavior. x86/Linux에서는 `SIGFPE`로 종료
- 이스케이프 문자는 따옴표 안에서만: `'\n'`(1바이트 `char`), `"\n"`(2바이트 문자열)
- `else`에는 조건을 쓰지 않음. 조건이 필요하면 `else if`
- 짝홀은 최하위 비트로 결정됨: `(n & 1) == 0`이면 짝수 (괄호 필수)
- 음수 나머지는 음수가 될 수 있음: `-3 % 2 == -1`. 홀수 검사는 `!= 0`이나 `else`로
- 출력 문자열은 공백과 철자까지 예시랑 정확히 맞추기

다음에는 최적화를 끈 `-O0`으로도 컴파일해서, 나눗셈 명령어(`idiv`)가 실제로 나오는지 `-O2`와 비교해 볼 예정이다.
