## 📌 문제 설명

두 정수 `a`, `b`가 주어질 때 다음과 같은 형태의 계산식을 출력하는 코드를 작성해 보세요.

```
a + b = c
```

### 제한사항
- $1 \le a, b \le 100$

### 입출력 예

| 입력 | 출력 |
|:---:|:---:|
| `4 5` | `4 + 5 = 9` |

---

## 📝 원본 코드 (제공된 코드)

```cpp
#include <iostream>
using namespace std;

int main(void) {
    int a;
    int b;
    cin >> a >> b;
    cout << a + b << endl;
    return 0;
}
```

---

## ❌ 처음 제출한 코드 (오답)

```cpp
int main(void) {
    int a;
    int b;
    int c = a + b;          // ① 입력 전에 계산
    cin >> a >> b >> c;     // ② 입력은 2개인데 3개를 읽으려 함
    cout << a << " + " << b << " = " << c << endl;
    return 0;
}
```

---

## ✅ 풀이 코드

```cpp
#include <iostream>
using namespace std;

int main(void) {
    int a, b;
    cin >> a >> b;          // 1. 먼저 입력
    int c = a + b;          // 2. 그 다음 계산
    cout << a << " + " << b << " = " << c << endl;
    return 0;
}
```

## 🤔 헤매었던 부분

### 1. 실행 순서

C++ 코드는 **위에서 아래로 한 줄씩** 실행된다.

- `int c = a + b;`는 **그 줄이 실행되는 순간의 값**으로 딱 한 번 계산된다.
- 엑셀 수식처럼 나중에 `a`, `b`가 바뀐다고 `c`가 자동으로 다시 계산되지 않는다.
- 그러니까 **입력(`cin`) → 계산 → 출력** 순서를 지켜야 한다.

### 2. 오답 코드의 실제 동작

| 단계 | 코드 | 결과 |
|:---:|---|---|
| ① | `int a; int b;` | `a`, `b`에 **쓰레기 값** (초기화 안 됨) |
| ② | `int c = a + b;` | 쓰레기 값 + 쓰레기 값 → `c`도 쓰레기 값 |
| ③ | `cin >> a >> b` | `a = 4`, `b = 5` 정상 입력 |
| ④ | `>> c` | 남은 입력이 없음 → **읽기 실패, `c`는 그대로** |
| ⑤ | `cout` | `4 + 5 = (쓰레기 값)` 출력 → 오답 |

> 💡 `cin >> c` 실패 시 동작 (g++ / libstdc++에서 직접 확인)
> - 입력이 그냥 끝난 경우(EOF) → `c` 값이 **바뀌지 않음**
> - 숫자 자리에 문자가 들어온 경우(예: `4 5 x`) → `c = 0` (C++11부터)
> - 두 경우 모두 `cin`에 `failbit`가 켜짐

## 🧠 왜 쓰레기 값이 들어갈까? (메모리 관점)

### 지역 변수는 Stack에 저장된다

`main()` 안에서 선언한 `a`, `b`, `c`는 **지역 변수(local variable)**이고, **Stack** 메모리에 저장된다.

```
        높은 주소
   ┌──────────────────┐
   │   이전 함수들이   │
   │   쓰고 남긴 데이터 │
   ├──────────────────┤ ← 함수 호출 전 Stack Pointer
   │  a : ??????????  │
   │  b : ??????????  │  ← main()의 Stack Frame
   │  c : ??????????  │
   ├──────────────────┤ ← 함수 호출 후 Stack Pointer
        낮은 주소
```

1. 함수가 호출되면 CPU는 **Stack Pointer(SP)를 옮겨서** 지역 변수가 쓸 공간을 확보한다.
2. 이때 컴퓨터는 **공간만 잡고 그 안을 0으로 지우지 않는다.**
3. 그래서 그 자리에 **전에 쓰던 데이터**(이전 함수 호출, 프로그램 시작 코드 등이 남긴 값)가 그대로 남아 있다.
4. 이렇게 의미 없이 남아 있는 값이 **쓰레기 값(garbage value)**이다.

### 왜 자동으로 0으로 지워주지 않을까?

- 성능 때문이다. 함수는 엄청나게 자주 호출되는데, 그때마다 메모리를 0으로 채우면 비용이 든다.
- C/C++은 **"안 쓰는 기능엔 비용을 내지 않는다(zero-overhead principle)"**는 철학이라, 초기화는 프로그래머에게 맡긴다.

### 전역 변수는 다르다

| 구분 | 저장 위치 | 초기화하지 않으면 |
|---|---|---|
| 지역 변수 | Stack | **쓰레기 값** (값이 정해지지 않음) |
| 전역 / `static` 변수 | Data / BSS 영역 | **0으로 자동 초기화** |
| `new`로 할당 (`new int`) | Heap | 쓰레기 값 (`new int()`로 쓰면 0) |

```cpp
int g;              // 전역 → 0

int main() {
    static int s;   // static → 0
    int x;          // 지역 → 쓰레기 값
}
```

### ⚠️ 쓰레기 값은 그냥 "랜덤한 수"가 아니다

- C++ 표준에서는 초기화 안 된 지역 변수를 **읽기만 해도 Undefined Behavior(UB)**다.
